# Ref - Protect agent identities with Microsoft Entra

## Microsoft Entra Agent ID로 에이전트 ID 보호하기 – 개념 정리

지금 보고 있는 문서는 **Microsoft Agent 365에서 사용하는 AI 에이전트의 “신원(Identity)”를 Microsoft Entra Agent ID로 어떻게 관리·보호하는지**를 설명하는 내용이에요.  
쉽게 말하면, “사람 계정 관리하듯이 AI 에이전트도 하나의 계정처럼 보고, 권한·보안·수명주기를 체계적으로 관리하자”는 개념입니다.

## 1. 전체 그림: Agent 365 + Entra Agent ID 역할 분담

- **Microsoft Agent 365**

    - **역할:** 조직 내에 존재하는 다양한 AI 에이전트를 “발견하고, 인벤토리(목록)로 관리하는 통합 레지스트리”
    - 즉, *어떤 에이전트가 어디에 있고, 무엇을 하는지*를 한눈에 볼 수 있게 해주는 플랫폼.
- **Microsoft Entra Agent ID**

    - **역할:** 이렇게 발견된 에이전트들에게 **“정식 ID(계정)”를 부여하고, 인증·인가·정책·보안**을 담당하는 **ID 및 접근 관리(IAM) 플랫폼**
    - 사람 사용자에게 Entra ID(옛 Azure AD)를 쓰듯이, 에이전트에게는 Entra Agent ID를 부여하는 느낌이에요.
- **핵심 포인트:**

    - Agent 365 → “에이전트가 어디 있는지, 어떤 에이전트가 있는지”를 관리
    - Entra Agent ID → “그 에이전트가 어떤 권한을 가지고, 어떻게 인증·인가되고, 어떤 보안 정책을 적용받는지”를 관리
    - 이렇게 역할을 분리해서 **대규모 에이전트 환경에서도 일관된 보안·거버넌스를 유지**할 수 있게 합니다.

## 2. AI 에이전트를 ‘ID’로 관리한다는 것의 의미

문서에서는 “에이전트를 다른 ID와 거의 동일하게 관리할 수 있다”고 표현해요. 이 말은 곧:

- **에이전트마다 고유한 ID를 부여**

    - 사람 계정처럼, 에이전트도 “누구인지”를 구분할 수 있는 ID를 갖습니다.
- **에이전트의 소유자·스폰서 지정**

    - 이 에이전트에 책임을 지는 사람(Owner/Sponsor)을 지정해서,

        - 누가 이 에이전트를 만들었는지
        - 누가 유지·관리 책임을 지는지  
를 명확히 합니다.
- **수명주기(Lifecycle) 관리**

    - 에이전트가 더 이상 필요 없을 때,

        - 자동으로 비활성화되거나
        - 권한이 회수되도록 워크플로를 구성할 수 있습니다.
    - 즉, “한 번 권한 주고 잊어버려서, 나중에 보안 구멍이 되는 상황”을 줄이는 거죠.

## 3. 거버넌스: 에이전트 스폰서·소유자·수명주기

문서에서 강조하는 **거버넌스(Governance)** 포인트는 크게 세 가지입니다.

1. **에이전트 스폰서십(Sponsorship) & 오너십(Ownership)**

    - **스폰서/오너를 지정**함으로써,

        - 이 에이전트가 어떤 목적을 위해 존재하는지
        - 누가 이 에이전트를 책임지는지  
를 명확히 합니다.
    - 규제 산업이나 보안이 중요한 조직에서는 “책임 소재”가 매우 중요하죠.
2. **에이전트 수명주기(Lifecycle) 워크플로**

    - 예:

        - 에이전트 생성 시 → 승인 프로세스
        - 일정 기간 사용 후 → 재승인 또는 자동 만료
        - 프로젝트 종료 시 → 에이전트 비활성화 및 권한 회수
    - 이런 흐름을 자동화해서, **에이전트가 필요 이상으로 오래 권한을 갖고 있지 않도록** 합니다.
3. **정책 기반 관리**

    - 에이전트 ID에도 **정책(Policy)을 적용**해서,

        - 어떤 리소스에 접근 가능한지
        - 어떤 조건에서만 접근 가능한지  
를 세밀하게 제어합니다.

## 4. 리소스 접근 보호: Zero Trust 원칙을 에이전트에 확장

문서에서 중요한 부분 중 하나가 \*\*“Zero Trust를 에이전트에게도 적용한다”\*\*는 점이에요.

- **최소 권한 원칙(Least Privilege)**

    - 에이전트에게는 **업무 수행에 꼭 필요한 권한만** 부여합니다.
    - 예:

        - 특정 SharePoint 사이트만 읽기 권한
        - 특정 API만 호출 가능
        - 특정 데이터베이스에 제한된 쿼리만 허용 등
- **조건부 액세스(Conditional Access for agents)**

    - 사람 사용자에게 적용하던 조건부 액세스를 **에이전트 ID에도 적용**할 수 있습니다.
    - 예:

        - 특정 네트워크 구간에서만 호출 허용
        - 특정 리소스에 접근 시 추가 검증
        - 위험도가 높을 때 접근 차단 등
- **위험 기반 보호(Risk-based protection)**

    - Microsoft Entra ID Protection for agents를 통해,

        - \*\*이상 행동(예: 평소와 다른 리소스 접근, 비정상적으로 많은 로그인 시도)\*\*을 탐지하고
        - 자동으로 대응(차단, 추가 인증 요구 등)할 수 있습니다.

## 5. Copilot Studio 에이전트와 네트워크 수준 제어

문서에서는 **Microsoft Copilot Studio로 만든 에이전트**에 대해 **네트워크 레벨 제어**도 언급합니다.

- **Secure Web and AI Gateway**와 연계

    - Copilot Studio 에이전트가 외부/내부 리소스에 접근할 때,

        - **웹 콘텐츠 필터링**
        - **위협 인텔리전스 기반 필터링**
        - **네트워크 파일 필터링**  
등을 적용해,
        - 악성 사이트 접근 차단
        - 민감 데이터 유출 방지  
같은 보안 통제를 할 수 있습니다.
- 요약하면,

    - 에이전트가 “어디로 나가고, 무엇을 가져오고, 어떤 파일을 다루는지”를 네트워크 레벨에서 통제하는 기능이라고 보면 됩니다.

## 6. Microsoft Entra 에이전트 ID 플랫폼 기능

문서 마지막 부분은 **“에이전트 ID 플랫폼”이 제공하는 기술적 능력**을 정리하고 있어요.

- **인증(Authentication)**

    - 에이전트가 리소스에 접근할 때,

        - **애플리케이션 전용(App-only)** 시나리오
        - **위임(Delegated)** 시나리오  
모두를 지원하는 **표준화된 인증 방식**을 제공합니다.
- **인가(Authorization)**

    - 에이전트가 “무엇을 할 수 있는지”를 세밀하게 제어하는 권한 모델을 제공합니다.
    - 예: 특정 API의 특정 메서드만 호출 가능, 특정 범위(scope)만 허용 등.
- **SDK 및 API 통합**

    - 개발자가 에이전트를 만들 때,

        - Entra Agent ID와 쉽게 연동할 수 있도록 **SDK와 API**를 제공합니다.
    - 이를 통해,

        - 에이전트가 조직의 보안·정책 프레임워크 안에서 자연스럽게 동작하도록 설계할 수 있습니다.
- **엔터프라이즈 환경에 맞춘 상호운용성**

    - 다양한 애플리케이션, 서비스, 보안 솔루션과 연동되도록 설계되어,

        - 기존의 Entra ID 기반 인프라와 **일관된 방식으로 에이전트를 관리**할 수 있습니다.

## 7. 정리: 이 문서가 말하고 싶은 핵심

한 줄로 요약하면:

> 
> **“AI 에이전트도 사람 계정처럼, Microsoft Entra Agent ID를 통해 정식 ID를 부여하고, Zero Trust 원칙 아래에서 수명주기·권한·보안을 체계적으로 관리하자.”**

조금 풀어서 정리하면:

- **에이전트는 이제 ‘익명 도구’가 아니라, 관리 대상인 ‘주체(Identity)’다.**
- Agent 365가 에이전트를 **발견·인벤토리화**하고,  
Entra Agent ID가 그 에이전트의 **ID·권한·보안·거버넌스**를 담당한다.
- 이를 통해:

    - 에이전트가 **무엇을, 어디까지 할 수 있는지**를 통제하고
    - **누가 책임지는지**를 명확히 하며
    - **필요 이상으로 오래 권한을 갖지 않도록** 수명주기를 관리하고
    - **Zero Trust와 조건부 액세스, 위험 기반 보호**를 에이전트에게도 그대로 적용할 수 있다.
